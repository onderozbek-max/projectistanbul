## 1. Verdict

v0.3 is a better game than v0.1 and v0.2. The core fight reads, the knife cold open works, and the elite and level-up spikes
land. But it is still **one level, one scene, four weapons and no skills**. The owner's nine points are not opinions. Each one
has a clear code cause:

1. Sound is 85 synthesized cue definitions (38 played in code), many built from noise. There is no music system.
2. Characters are a single drawing routine: stroked limbs, a torso and a head blob.
3. Hero and weapon animation is ad hoc. There is no four-beat spec.
4. Wow moments are not planned per run. There is no spike plan.
5. There is one street scene (İstiklal). It has no per-neighbourhood look.
6. Four weapons and no skills. The player's only decision is where to walk.
7. This audit.
8. The director is hard-coded to level 1. There is no level data, so levels 2–100 cannot be added by data.
9. Story is about 30 lines, with subtitles that vanish and barks that expire. Calls do not change play.

The v0.4 plan covers all nine. The biggest risks are not the features. They are **(a)** a flat difficulty curve that depends on meta power the prototype does not have yet,
**(b)** art and audio production load, **(c)** the age rating and guardrails with red blood, and **(d)** performance and determinism on a low-end phone, which nobody has measured.

**What is good and should stay:** the auto-attack with a single thumb, the knife grab in the cold open, the 60-second hold with the rising spawn curve, the elite chest, the level-up shockwave, the readability rules, the telemetry, and the bot.

### 3.9 Tech risks

| # | Finding | Pri | Recommendation |
|---|---|---|---|
| T-1 | **Performance is not measured on a low-end phone.** Each figure is about 15–20 path draws with strokes and shadows. No batching. At 300 enemies that is thousands of draws. `perf_sample` exists but has no device data. In v0.4 the skills code copies the enemy list each step (`S.snap = s.enemies.slice()`), and the director filters enemy arrays each tick. | P0 | Measure on iPhone 11 (Low reference, PRD §6) at 300 enemies. Record p95 frame time and sim ms per tick. Fix the per-step copies before the frame budget is spent. |
| T-2 | **Determinism was broken in v0.3.** `sim/weapons.js` (v0.3 read) called `Math.random()` for canister spin inside sim state, so seeded replays drifted. PRD §6 requires identical results for identical seed and inputs. Checked on 2026-11-08: the in-flight E1 code has no `Math.random` under `prototype/js/sim/`; the remaining calls are in view files (`fx.js`, `sprites.js`, `weapons-fx.js`, `istanbul.js`, `sfx.js`), which is fine. | P1 | Keep it that way: add a grep check and a golden-seed test to CI (T-6). Confirm the canister fix survives integration. |
| T-3 | **Audio.** `noise()` builds a new AudioBuffer on every call (up to 0.6 s). Sequences run on `setTimeout`, so they drift under load. No voice limit beyond a minimum gap. | P1 | Pre-render cues (A). Add voice limits (DS §15 priority). Test on iOS Safari (unlock on gesture is already in `P.Sfx.unlock`). |
| T-4 | **Canister and cluster targeting** scan all enemies for each candidate (O(n²)). Fine at 300 enemies once, but it repeats per projectile. | P2 | Use a spatial hash (architecture §4.2) before the Godot port. |
| T-5 | **Godot port path.** The sim is mostly pure (no DOM), which helps. What ports: numbers (config → JSON → `.tres`), journey data, director logic, state machines. What does not: canvas figures (rebuild as Skeleton2D and MultiMesh), WebAudio synths (pre-render to OGG at build), DOM UI (rebuild in Control nodes). The sim uses object arrays. The architecture needs struct-of-arrays (§4.2) for 300+ enemies. | P1 | Keep the JS sim as the design oracle until M2. Write one JSON schema for weapons, journey and bosses. Generate both the JS config and the Godot `.tres`. Port the bot to a headless Godot run (`tools/bot_sim.gd`, architecture §6). |
| T-6 | **Test coverage.** Only the bot checks balance. No golden tests, no screenshot tests. | P2 | Add `test-arsenal` (E1) and a journey generator test (E2) to CI before M2. |
| T-7 | **Config duplicates the docs.** Numbers live in `config*.js`, in docs, and in fork-era names. | P2 | One source (JSON), then generate. Covered by T-5. |
